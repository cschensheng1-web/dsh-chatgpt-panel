- 独立 DSH Host 加载验证：使用本机官方 0.2.1-rc.5 的运行时与独立 DSH_HOME，安装真实交付目录，确认插件进入客户端启动清单，并确认 GET `/api/dsh-chatgpt-panel/state` 返回 200、实验开关为 false。进一步在该运行时的真实 Web UI 打开 Chat 主面板并切回原生 Conversation，浏览器无页面异常。仅隔离 profile，无用户模型配置或真实对话。详情见 [Host 验证记录](HOST-SMOKE.zh-CN.md)。

## 可自行复现

在源码目录运行：

```sh
npm ci --ignore-scripts
npm run check
npm run test:ui
npm run test:dom
```

`test:ui` / `test:dom` 需要本机已安装 Google Chrome。测试启动的无头 Chrome 仅访问本地合成页面；它与生产插件中保持可见的官网 Chrome 是不同测试环境。某些受限执行环境需要允许本机浏览器进程和仅本机监听。

## 实机验收步骤

1. 安装前记下 DSH 和 Chrome 版本。确认原生 Agent 能打开既有对话。
2. 按 README 安装本地插件。检查侧边栏出现 DeepSeek Chat，首次输入框不能发送。
3. 点击 Agent，确认回到同一个原生会话。不要为验收专门启动付费 Agent 任务。
4. 返回 Chat，先点官网入口确认手动官网可正常使用。官网入口的内建 Browser 登录与专用 Chrome 登录相互独立。
5. 启用实验连接，打开可见 Chrome，在官方页面自行登录。发送一条无敏感内容的短问题，比较官网与面板内容。
6. 新建第二条对话，再选第一条发送不同短问题，核对 Chrome 导航地址和回复归属。若无法确认，停止测试并改用官网。
7. 测试代码块、复制、停止。停止或超时后应保留部分内容并要求核对官网，不能自动重复发送。
8. 若遇到验证码、限流或不支持的页面，应出现暂停提示且无重复请求。手动处理后可新建插件对话；不通过修改安全设置恢复自动化。
9. 重启 DSH，确认本地历史仍在、实验开关恢复关闭。禁用/卸载插件后，确认原生 Agent 照常打开。

## 升级后回归

每次 DSH 更新至少检查：入口 → 打开 Chat → 返回 Agent → 禁用插件。每次 Chrome 或官网页面变化后，再检查一条新对话、一次历史续聊、一次停止。若有任何消息归属不明确或发送未确认，先核对官网，禁止直接连点重发。

版本 0.1.0-preview.8；2026-11-06。项目界面实测日期为 2026-11-02。

## 自动化

- `npm run check`：生产构建 + 50 项单元测试，其中新增 35 项工具请求兼容测试。覆盖隔离容器生命周期、失败清理、安全导航、刷新、显式读取与关闭/导航后的快照失效、项目存储隔离、恢复与保存失败保护、来源 URL 清理、完整交接文本、同项目原生草稿、失败重试、已有草稿不覆盖、取消导航、Work 公开回复筛选。
- `npm run test:ui`：使用实际生产 bundle 和本地模拟 Desktop/DSH 服务，验证显式读取、核对文本、创建指定工作区草稿、零自动发送、项目隔离、刷新恢复、Work 回复读回与复制、失败保留原内容。
- 同一 UI 测试将真实快照函数放入拦截提供的本地 HTML，验证消息角色、代码块、选中文字、密码/输入/侧栏/隐藏推理排除、验证码、生成中、未知布局、过长与错误域名。没有真实 DeepSeek 网络请求或真实账号。

## 本机项目界面实测

使用官方 DSH Desktop 0.2.1-rc.5 / macOS arm64 的本地目录安装：

- 项目选择、Chat/Work 页签、真实官网首页、资料区和原生会话“项目 Chat”入口可见。
- 实际调用内嵌 webview 的只读快照能力成功；官网首页没有聊天时，返回“没有识别到已加载的聊天消息”并显示手动导入，没有开启外部 Chrome。
- 使用明确标识的合成验证文本，将项目资料、聊天上下文和任务组成 327 字交接，创建在实际所选工作区并填入原生 DSH 输入框。
- 原生输入框仍显示“发送消息”，处于未发送状态；当前默认 Agent 模式和模型由 DSH 自身提供，插件没有主动发送或切换权限。验证后已清空合成原生草稿，发送按钮恢复禁用。

真实官网登录后的消息容器与完整捕获尚未验证，不能将本地夹具通过视为真实账号对话已通过。
